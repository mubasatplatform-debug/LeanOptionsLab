# سجل تدشين LeanOptionsLab على الخادم

هذه وثيقة أثر تشغيلي، وليست ادعاء بأن نظام تداول حي منشور.

| البند | القيمة |
| --- | --- |
| جذر الإصدار | `/opt/lean-options-lab` |
| إصدار المستودع | `21d4e462b0c2ba7fb103f114ffba14721f3c66f6` |
| إصدار LEAN | `abeb0a0627ec484b92291c45c3f2553726c26199` |
| .NET SDK | `10.0.400` |
| النمط | تشغيل batch عند الطلب |
| خدمة ويب أو منفذ | لا يوجد |
| تداول أو اتصال سوق حي | لا يوجد |

أُعيد فحص هذه الحقائق قراءةً في 2026-09-02. الرابط `current` ما زال يشير إلى الإصدار أعلاه، وتوجد نتائج تشغيل سابقة، لكن بيانات SPY المطلوبة غير موجودة. لذلك النجاح التشغيلي هنا يعني أن المحرك يبني ويشغّل ويصدر تقرير `invalid-data` صحيحاً؛ لا يعني Backtest صالحاً ولا نظاماً متاجراً.

## ما يلزم قبل إعادة تدشين إصدار جديد

1. يجب أن تكون بوابة الجودة المحلية كاملة ناجحة برمز خروج `0`.
2. يجب أن يكون Git SHA المراد نقله محدداً، مع إبقاء الشجرة الحالية للمستخدم دون reset أو stash.
3. يُثبت الإصدار في مجلد جديد قابل للرجوع، ثم يتحول رابط `current` فقط بعد Smoke ناجح.
4. يُشغّل Backtest عديم الأوامر وتُراجع `finalStatus` وعدادات البيانات.
5. إن فشل Smoke، يبقى `current` على الإصدار السابق ولا تُحذف ملفات النتائج.

لا يوجد سكربت نشر متتبع حالياً، ولم يُنفذ في هذه الجولة تغيير على الخادم. المسار السحابي الموصى به لإثبات البيانات موثق في [DEPLOYMENT.md](DEPLOYMENT.md).
